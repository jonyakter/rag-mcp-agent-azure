## Critical Reflection on AI Usage

Per the grading rubric (Section 4), this section documents engineering judgement applied to AI output — not just acceptance.

**What AI consistently got right:**
- Class structure and interface compliance — tool, repository, and service classes matched ITool, IExperiment, IStorageProvider, IDocumentRepository contracts once signatures were explained.
- Root cause analysis — SQL timeout, IHttpClientFactory anti-pattern, DummyEmbeddingService fallback, and UTC DateTime issue were all correctly identified.
- MCP server scaffolding — Program.cs builder pattern, WithTools<>() registration, and MapMcp endpoint were correct on first attempt.
- Azure configuration documentation — double-underscore separator for Application Settings is not obvious; the AI's explanation saved significant debugging time.

**What consistently required manual correction:**
- SDK API surface: InvokeToolAsync → CallToolAsync; HttpClientTransport constructor → HttpClientTransportOptions. AI recalled names from a different SDK version; confirmed by DLL reflection.
- Architecture violations: AI placed OpenAI embedding in the agent (3 occurrences), added queue polling despite explicit no-queue instruction, and added duplicate AddScoped conflicting with .WithTools<>().
- Configuration values: connection string key names, threshold 0.25 → 0.30, runtime flag DOTNET → DOTNETCORE, constant value 10 → 5. All required checking against real appsettings.json and Azure CLI docs.
- Missing safety guards: DeleteByFileNameAsync idempotency, UTC conversion for Table Storage, blob URL path extraction, null/type checks on IExperimentResult — none present in AI's first output.

**Decisions made by the team, not by AI:**
- No-queue architecture: EXPERIMENT_INPUT env-var read on first Receive() call, null thereafter — keeps Program.cs while-loop unchanged with no Azure Queue resource needed.
- Stateless MCP HTTP transport: required for Container Apps multi-replica deployment; AI defaulted to stateful.
- McpContracts.cs placement in Common: team identified wrong dependency direction; AI placed shared types in the consuming MCP project.
- DeleteByFileNameAsync added to IDocumentRepository after discovering duplicate rows during IngestDocument manual testing.
- Debug commands in ChatSession (/preview, /similar, /embed): added after integration testing showed need to test individual MCP tools in isolation.
